# Decisions log

Decisions made during design and implementation without the user in the loop (the user delegated them
on 2026-10-13). Newest last. "chinwag" is the terminal client the library was first built for; it
has since been retired in favour of `ic3-irc`, so entries about its TUI are history only.

| # | Date | Decision | Why |
|---|---|---|---|
| 1 | 2026-10-13 | Live capture (§9 of the spec) is deferred to a single user-run verification checklist at the end, instead of a milestone before `events`/`store`/TUI. Fixtures are written from purple-teams' documented shapes. | Live sign-in requires the user (the agent's own token acquisition was blocked by the permission classifier) and the user is away until completion. |
| 2 | 2026-10-13 | purple-teams is used as protocol reference only; no code copied. Proposed licence `MIT OR Apache-2.0`, to be confirmed by the user before publishing. | purple-teams is GPL-3.0. |

| 4 | 2026-10-13 | TUI split: tokio engine owns all data/network and publishes `Arc<ViewModel>` snapshots; UI on its own OS thread, woken by a channel (no polling); quit is handled locally by the UI so it always works. | User asked for rendering separated from work from day one; review found deadlock/shutdown pitfalls in the first draft. |
| 5 | 2026-10-13 | Tuning constants: engine publishes ≤30/s; command queue 256; event channel 1024; wrap-cache entries evicted after 120 unused draws; `thread()` ≤4 concurrent; engine shutdown timeout 2 s. | Reasonable defaults; all are single constants, easy to change. |

| 14 | 2026-10-13 | A sent message keeps its pending key until the server's copy (echo/refetch) arrives; the `201` only marks it sent.
