# Unverified protocol assumptions

Every `UNVERIFIED(§9.N)` site in `crates/*/src`, one row each: the function (or constant) that holds
the guess, the shape it assumes, the smoke step and capture file that answer it, and what "wrong"
looks like. A FAIL from the smoke tool maps to exactly the function named in its row, so that is the
only code to change. The Result column is filled in by the user's verification run
(docs/verification.md).

**How to run.** In a terminal, signed in to your own Teams account (the tool reuses ic3-irc's session,
or shows a device code the first time):

```text
cargo run -p ic3-teams --example smoke -- rest                     # read-only; lists your chats for --conv
cargo run -p ic3-teams --example smoke -- csa                      # read-only; CSA token and user state (counts only)
cargo run -p ic3-teams --example smoke -- --conv '<id>' all        # rest, csa, write, then events (3 minutes)
cargo run -p ic3-teams --example smoke -- --conv '<id>' write --typing   # also §9.18: needs someone watching the chat
cargo run -p ic3-teams --example smoke -- --conv '<id>' write --only 9.7,9.7b   # only those items (and the steps they need)
cargo run -p ic3-teams --example smoke -- --conv '<id>' events --minutes 75   # §9.5: spans a Skype-token renewal
cargo run -p ic3-teams --example smoke -- --conv '<id>' --no-reconnect-on-renewal events --minutes 75
```

The Skype token lives about 64 minutes (`expiresIn` ≈ 3831 s measured) and is renewed at 80 % of
that; 75 minutes outlasts the old token too. The `--no-reconnect-on-renewal` run answers §9.5 itself
(the default run only shows that the reconnect works); the tool prints the expiry and renewal times up
front and warns when the run is too short. The full walk-through, prompt by prompt, is
[docs/verification.md](verification.md). Writes go only to `48:notes` or the `--conv` chat. Each §9
item prints one `PASS` / `FAIL` / `UNVERIFIED` line (§9.10 prints `INFO`: it is informational and
never fails) with the capture file holding the evidence, and the run ends with a summary table to
paste back.

**Captures** land in `./captures/smoke-<timestamp>/` (or `--capture <dir>`), one redacted JSON file per
HTTP exchange or trouter frame: `NNNNNN-http-<label>.json` and `NNNNNN-ws-<in|out>-<label>.json`,
where `NNNNNN` is a sequence number and the label is lowercased with anything outside `[a-z0-9-]`
turned into `-` (so `mark_read` is captured as `-http-mark-read.json` and `fetchShortProfile` as
`-http-fetchshortprofile.json`). The patterns below use `*` for the sequence number. Captures hold no
tokens but do hold real chat content: keep them private.
